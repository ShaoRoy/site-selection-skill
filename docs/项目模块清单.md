## 三处相对昨天的更新

### #6 否决检查：70% → 95%

**原问题**：工具描述写「执行一票否决检查…返回硬性否决项」，报告第 5 段却写「场地核查（提醒，非否决）」，而实际流程里 `hard_vetoed` 只打印一行日志、从不中断。三处语义打架。

**v2.9.3 修法**：按产品原则（系统不判能不能开）统一为「提醒」定位——

| 位置 | 现在 |
|---|---|
| 工具描述 | 「硬性条件核查…只提醒，不裁决，也不中断分析流程」 |
| 输出 | `positioning: 'advisory'` ＋ `blocks_pipeline: false` |
| 字段说明 | `hard_vetoed` = 是否命中硬伤规则，**不代表不能开** |
| 运行日志 | 「硬伤 X 项（提醒，不中断）」 |

### #12 参数覆盖：85% → 95%

**原认知**：单店级覆盖「只在文档」。
**实际**：代码早就通了——`run-site.mjs` 会读 `params/<store_id>.json` 并作为 `overrides` 传进 `financial_calc`。

**真正的问题**是路径写死（`../../.dsh/skills/site-report/params/`），只在 `scratch-plugin/tools/` 这个位置成立，包内上两级跑到包外。
**v2.9.4 修法**：改为多候选依次尝试（包内 `../params/` → dev `.dsh/` 回退），未命中时打印「按业态默认值测算，这不是错误」。

## 关于「腾讯人口热力」：已移除，不是未完成

核查结果：全项目 **0 处**热力实现代码，只剩两条说明文字。

**移除原因**：腾讯人口热力需企业资质才能调用，个人拿不到。

**替代方案**（已实装并跑通）：

| 原热力想回答的问题 | 现在用什么答 |
|---|---|
| 这块地方人多不多 | WorldPop 2020 常住人口栅格（500m / 1000m / 3000m 三圈，93m 精度） |
| 人是来住还是来上班 | 职住比（写字楼 POI ÷ 住宅区 POI） |
| 消费力强不强 | 咖啡 / 银行 / 高端餐饮密度 |
| 客流旺不旺 | 配套成熟度 ＋ POI 代理强度 ＋ 交叉判定 |

## 已知设计取舍（不是缺陷）

- **人口数据**：不接腾讯热力，用 WorldPop 栅格 ＋ POI 代理；报告明确标注「代理指标，不是实测人口」
- **动线阻断**：引擎算不准就不算，交现场实测并录入，报告标「现场实测」
- **否决检查**：只提示不裁决——证照与合规由承租方办理，系统不判「能不能开」
- **座位翻台 vs 桌翻台**：全部用座位翻台（客流 ÷ 座位数），桌翻台只作参考列，两套口径不混用
- **缺数据**：一律显式写「本段未执行」并给补齐命令，不塞空数据、不静默兜底
