## 关于「腾讯人口热力」：已移除，不是未完成

原表把它列为「❌ 20%：MCP 未接入，全靠降级路径」。**实际已从项目中删除。**

核查结果：全项目 **0 处**热力实现代码，只剩两条说明文字：

- `scripts/demand-fetch.py` 文件头：「用 POI 密度与业态结构**替代「人口热力」**，全部免费、可复核」
- `data/population/` 里一个示例 JSON 的注释：「示例数据，**不是**腾讯热力实时值」

**移除原因**：腾讯人口热力需企业资质才能调用，个人拿不到。

**替代方案**（已实装并跑通）：

| 原热力想回答的问题 | 现在用什么答 |
|---|---|
| 这块地方人多不多 | WorldPop 2020 常住人口栅格（500m / 1000m / 3000m 三圈，93m 精度） |
| 人是来住还是来上班 | 职住比（写字楼 POI ÷ 住宅区 POI） |
| 消费力强不强 | 咖啡 / 银行 / 高端餐饮密度（品牌密度代理） |
| 客流旺不旺 | 配套成熟度 ＋ POI 代理强度 ＋ 交叉判定 |

所以这一项不是「差 80%」，是**换了技术路线，已完成**。

## 已知设计取舍（不是缺陷）

- **人口数据**：不接腾讯热力，用 WorldPop 栅格 ＋ POI 代理；报告明确标注「代理指标，不是实测人口」
- **动线阻断**：引擎算不准就不算，交现场实测并录入，报告标「现场实测」
- **否决检查**：只提示不裁决——证照与合规由承租方办理，系统不判「能不能开」
- **缺数据**：一律显式写「本段未执行」并给补齐命令，不塞空数据、不静默兜底
