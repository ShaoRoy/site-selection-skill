# 决策与踩坑记录（DECISIONS）

> 用途：把「为什么这么做」和「踩过的坑」固化下来，避免下次重犯。
> 只记有代价的决定，不记显而易见的。

---

## 一、口径决策

| # | 决定 | 理由 | 反例代价 |
|---|---|---|---|
| 1 | **税费与摊销必须进模型**（fin-v3） | 只扣「租金+人力+其他」会系统性高估净利，回本看起来比行业短一半 | 珠江新城案例：23.9 月 → 修正后 57.4 月（行业基准 51.9），差一倍多 |
| 2 | **现金口径 / 会计口径分开** | 摊销不是现金支出，拿来算回本会虚长；算净利率又必须扣它 | 混用会同时得罪"多久回本"和"净利率"两个问题 |
| 3 | **谈判锚点取基准档，保守档仅作压力下限**（v2.10.8 改） | 锚点是「可接受的价格上限」，应按常规经营预期；压力测试是风险提示，不是出价依据 | 旧口径取最保守会报「需降 77%」，与同报告里租售比健康、回本优秀自相矛盾；**保本红线仍取最保守** |
| 4 | **比值校验不依赖外部数据** | 点评/月售可刷、房价有偏，外部数据不可靠 | 用可刷数据验证模型 = 用脏水洗衣服 |
| 5 | **截流分两轴**（L1–L5 点位力 × none/light/heavy 竞争压力） | 场地属性与竞争属性是两回事 | 用 L4 替代 heavy 会漏掉"位置好但对手强"这一类 |

## 二、数据源决策

| # | 决定 | 理由 |
|---|---|---|
| 6 | 人口热力**停用但不删** | 个人无法开通企业资质；客户若在企业有权限，设 `POPULATION_ENABLED=1` 即可 |
| 7 | 需求侧用 **POI 代理**（住宅密度/职住比/咖啡银行密度） | 免费、自动、抗刷；人口数据无公开 API |

| 9 | 行业基准库**编译进代码**（`src/benchmark-data.ts`） | 插件无 Node 类型定义，运行时零文件 IO；底稿更新重跑 `import-benchmarks.py` |

## 三、架构决策

| # | 决定 | 理由 |
|---|---|---|
| 10 | 报告段数固定 **7 段 + 附录**，与 `report.mjs` 逐段对应 | 之前 SKILL 写 6 段、实际 8 段，编号错位 |
| 11 | **入口收敛为 4 条命令** | 20+ 脚本记不住就不用 |
| 12 | 工具跑完**自动留痕**（status.json → registry → index.md） | 手工维护的表没人能坚持三个月 |
| 13 | 网格编号用**经纬度**，不按城市切 | 城市边界会变；经纬度全球唯一、永久有效 |

## 四、踩过的坑（同类错误别再犯）

| # | 坑 | 教训 |
|---|---|---|
| 1 | **输出目录按业态命名** → 换地址覆盖上一份报告 | 任何输出路径必须含点位标识 |
| 2 | 归档脚本时只 `move` 文件，**没改 import** → probe 直接崩 | 移动文件必须全库搜引用 |
| 3 | 网格扫描第一版用**绝对阈值** → 竞争项全顶 100、全是 C 档 | 跨片区比较必须**分位归一化 + 排名分档** |
| 4 | 敏感度 `每座面积 ±20%` **座位增减方向写反**（测试抓到） | 表格看起来毫无破绽，人眼审不出 |
| 5 | 报告「距锚点需降 **-66165**」→ 负数被当成需降 | 负值含义必须显式翻译成「无需降，尚有余量」 |
| 6 | html 缺「建议租金」整块，md 有 | md 与 html 必须逐块对照 |
| 7 | `Select-String` 用 `$_` 在 catch 块里，`$_` 已变成错误对象 → 判空失败 | PowerShell 陷阱 |
| 8 | PowerShell `Get-Content -Raw` 默认非 UTF-8 → 搜中文全失败 | 读 UTF-8 文件一律加 `-Encoding utf8` |
| 9 | 插件不能 `import 'node:fs'`（无 `@types/node`） | 改用生成式数据模块 + `allowImportingTsExtensions` |
