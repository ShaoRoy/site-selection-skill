# 选址智能系统 · 功能总览

> 连锁实体商业（餐饮）选址评估工具。
> **Tool 硬算 + Skill 只翻译**：确定性计算全部在 TypeScript 工具里，大模型只负责把结构化结果翻译成人能读的报告，**不允许自己算数、编数**。

---

## 二、四道筛选流程

```
第 1 筛   城市网格扫描        全城 → 30 个候选点位
```

## 三、第 1 筛：城市网格扫描

| 功能 | 说明 |
|---|---|
| 锚点取样 | 以「地铁站 + 商场」为锚点，300m 内自动合并 |
| 切片采集 | 全城 POI 一次性拉取在本地聚合，**比逐点查询省 90% 调用** |
| 五维打分 | 住宅密度 30% / 职住比 20% / 咖啡密度 25% / 配套 25%，减竞争压力 ×k |
| 分位归一 | 分数为本批内相对值，A/B/C 按排名分档（跨片区可比） |
| 推荐理由 | 每行生成一句话：「需求强但竞争激烈，得靠差异化」 |
| **额度硬门** | 默认 dry-run 只估算；>500 次需 `--yes`，>1500 次直接拒绝 |
| **零调用重排** | `--rescore` 复用采集快照改权重，0 次 API |
| 网格编号 | `G{纬度}_{经度}`，全球唯一、不随城市边界变化 |
| 覆盖管理 | 状态机（未扫描→已扫描→已评估→已现场→候选池/已否决/已签约）+ 覆盖地图 + 进度看板 |

## 四、第 1.5 筛：单点评估

### 竞品格局

| 功能 | 说明 |
|---|---|
| 双源采集 | 高德 + 腾讯，含覆盖率统计 |
| 三重去重 | 同名同点 ≤50m / 跨源同坐标 ≤30m / 跨源名称相似 ≥0.6 + ≤100m |
| 客单价硬分层 | 按 POI 实际人均重判规模段，覆盖店名猜测 |
| **三级分层** | 直接竞品（同品类同价位）/ 替代（同品类不同价位）/ 间接（不同品类） |
| 品牌聚合 | 同品牌多店、最近距离 |
| Voronoi 归属 | 本点位落在哪家竞品的势力范围内 |

### 截流两轴（核心差异点）

| 轴 | 问什么 | 来源 | 输出 |
|---|---|---|---|
| **点位截流力** | 这个铺位能自然截住多少路过客流 | **现场判定** | L1~L5 + 客流乘数 |
| **竞争截流压力** | 对手会抢走多少 | POI 推算 | none / light / heavy |

**L1–L5 等级**：L1 顶级（×1.30）/ L2 强（×1.10）/ L3 中等基准（×1.00）/ L4 弱（×0.65）/ L5 极低（×0.15）

两轴**不能互相替代**：前者调客流，后者调风险，报告里分两行写。

### 空间与可达

| 功能 | 说明 |
|---|---|
| 等时圈 | Valhalla / OSRM 本地路网；都不可用时降级直线估算并标【估算】 |
| 多圈层 | 内圈看直接对手（报份额），外圈看辐射（只报距离带） |
| 网格 Voronoi 份额 | Top1 / Top3 集中度 |
| 交通可达 | 最近地铁站、停车场、300m 内停车场数 |

## 五、需求侧代理指标（替代人口热力）

人口热力需企业资质，个人无法开通 → **用 POI 结构做代理**：

| 指标 | 代理什么 |
|---|---|
| 住宅密度 | 居住人口密度 |
| 职住比 | 就业 vs 居住结构 |
| 咖啡密度 | 消费力（星巴克选址同款逻辑） |
| 银行密度 | 商务活动强度 |
| 高端餐饮密度 | 宴请需求 |
| 配套成熟度 | 商场 + 学校 + 地铁数量 |

输出 **综合需求强度 0~100**，附数据完整度、置信度、每项的**已知偏差**。

配套保护：QPS 节流 + 指数退避、**数据质量审计**（区分"当地真是 0"与"接口没给数据"）、**日配额记账**。

## 六、第 2 筛：现场

| 功能 | 说明 |
|---|---|
| 批量步行距离 | 高德步行路径规划，一次算 50 个目标，输出绕行倍数 |

| 自然语言反馈 | 现场口述四要素（目标/通不通/多远/什么挡着）直接生成数据 |

## 七、财务测算

### 三档情景 + 双口径

```
现金口径：毛利 − 税费 − 固定成本        → 回本、保本、极限租金
会计口径：现金净流 − 折旧摊销           → 净利率、ROI（与行业基准可比）
```

**为什么分开**：摊销不是现金支出，拿来算回本会虚长；算净利率又必须扣它。

### 输出模块

| 模块 | 内容 |
|---|---|
| 三档测算 | 营收 / 净利 / ROI / 保本日营业额 / 回本（双口径） |
| **极限租金反推** | 保本上限 + 目标回本上限，负值原样呈现不归零 |
| **建议租金锚点** | 锚点取**基准档**，保守档作压力下限并列；给出"距锚点需降"或"无需降，尚有余量" |
| **租期现金流** | 年递增、翻新周期、租期内回本月份、期末累计现金、租期容纳检查 |
| **空间容量对账** | 厨房/营业面积、座位数、翻台率、坪效、单方造价、面积产能校验 |
| **内部比值校验** | 毛利率/人力占营收/租售比/单方造价 vs 业态区间，越界给反推值 |
| **假设台账** | 逐条列出"不是你亲口给的数"，标来源与建议动作 |
| **双维敏感度** | 财务侧 × 空间侧各参数 ±20%，看结论是否翻转 |
| **计算口径附录** | 27 行公式 + 本次代入值 + 结果，参数错了能一眼定位 |

### 参数体系

```
本次传参 > params/<store_id>.json > params/<业态>.json > 内置默认
```

所有经验系数（回本、租售比、厨房占比、每座面积、翻台、坪效、租期、税费、摊销、截流乘数）**全部可覆盖**，改系数不用改代码。

## 八、行业基准对标

| 项 | 内容 |
|---|---|
| 数据 | **19 城 × 48 业态**，912 行（面积/投资/租金/客单/客流/净利率/回本） |
| 比对项 | 营业面积、初始投资、月租金、客单价、月营业额、会计回本、净利率 |
| 判定 | 偏离超 ±30% 报警（底稿自述单店实际 ±30%） |
| 定位 | **现实性校验，不替代单店实测**；禁止用基准值反向覆盖客户数据 |

## 九、报告

固定 **7 段 + 附录**，md + html 双版本：

```
0 结论
1 数据质量（含采集可信度）
2 竞品分布（2.1 内圈份额 / 2.2 外圈距离带 / 2.3 截流两轴 / 2.4 三级分层 / 2.5 动线阻断）
3 交通可达（含实测步行修正）
4 需求侧代理指标
5 场地核查（提醒，非否决）
6 财务测算（极限租金→建议租金→租期→空间→比值→台账→敏感度→基准对标）
附录 计算口径
```

配套产物：`probe.json`（所有数字的出处）、`map.html`（独立交互地图）、`survey.json`、`segments-review.csv`（人工核对分段）。

## 十二、设计原则

1. **判断留给读的人，系统只列证据**——不输出"能不能开"，只输出"还差哪几个数"
2. **每个数字可追溯**——公式、代入值、结果全列出
3. **缺省必须披露**——用了默认值就写进台账，不静默兜底
4. **不许用可刷的数据验证模型**——点评评分/月售一律不采
5. **不许为了凑结论反向调参**——参数是校准现实的，不是校准结论的
