## 渲染成 HTML（唯一交付形态）

九段骨架的**最终载体是 HTML**，不是 Markdown。渲染器：

```bash
python scripts/report-html.py --result <finance结果.json> --meta <上下文.json> --site "<点位>" --out out/reports
```

渲染层**不做任何再计算**，所有数字原样取自引擎输出。九段与 HTML 区块的对应：

## 场景 1 · 第 1 筛（商圈初选）该填哪几段

只需填 4 段，其余标「本筛不涉及」：

| 段 | 填什么 |
|---|---|
| 【结论】 | 本批候选 Top N 与排序依据（说明「分数是本批内相对值，不能跨批次比较」） |
| 【数据质量】 | 网格扫描的 API 消耗、覆盖率、锚点合并数 |
| 【竞品格局】 | 每个候选点的一句理由，不展开三级分层 |
| 【下一步】 | 建议踏勘哪几条主街、为什么 |

## 写法对照（与人格层语言规范一致）

| ❌ 不写 | ✅ 写 |
|---|---|
| 硬性否决：无排烟 | 排烟条件未核实（影响：无法通过环评） |
| 这个铺不能开 | 待核实 3 项，其中环评类别影响开业周期 1~3 个月 |
| 建议压价 3000 | 基准档静态回本 23.9 个月，保守档 44.5 个月 |
| 客流不足 | 日均客流 143 人，翻台率 0.52，该面积常规产能 2.0 |
| 竞争激烈 | 内圈 10 分钟内 15 家，最近 27 米，Top3 集中度 36.7% |

**形容词换成数字，判断换成事实。**

## 三个不许出现的东西

1. **裁决措辞**：「建议签约 / 直接放弃 / 强烈否决 / 能不能开」——系统只给证据与缺口。
2. **旧口径的人口与热力**：不再引用「位置大数据 / 人口档位 / 腾讯人口热力」。人口只来自 WorldPop 栅格，且必须标「常住人口，非客流」。
3. **第二套骨架**：只有本文件这套九段。若某处还写着 A/B/C 三阶段投决报告，那是旧版残留，以九段为准。
