# 业务侧使用指南（不写代码，只讲怎么用）

> 这份给**提需求的人**：怎么开口、哪些数字能改。
> 接口、坐标系、脚本参数这些技术细节在 `README.md` 和其余 `references/` 里，这份不重复。

## 一、它到底回答什么问题

给一个铺位，它回答三件事：

1. **这块地方值不值得去谈**——周边有多少人、有多少对手、人怎么走过来
2. **这铺一天要卖多少才不亏**——把月租、人力、毛利率代进去，反推保本营业额（不需要你先估营业额）
3. **租金谈到多少才不亏**——保本租金是多少、按你的回本要求最高能出到多少
4. **最可能栽在哪**——排烟/电量/消防/层高这些现场条件缺什么，哪几个数字估错了结论会翻

它**不回答「这店能不能开」**。证照、环评、消防验收由承租方去办，系统只列「待核实 N 项」，
不做裁决——判错一次就会误导决策，所以这条是硬规矩。

## 二、怎么提需求（说三句话就够）

### 三句话分别是

| 第几句 | 说什么 | 说多细 |
|---|---|---|
| 1 | **在哪** | 城市 + 地址；商场店说清楼层和铺号，街铺说清路口或门牌 |
| 2 | **做什么** | 业态（粤菜 / 茶楼 / 咖啡 / 火锅…）+ 面积（㎡），有层高更好 |
| 3 | **钱怎么算** | 月租金；有的话再加毛利率、初始投资（日营业额不用你估，见下） |

### 说到哪一步，决定你能拿到什么

| 你给到的信息 | 能出的结果 | 多花的代价 |
|---|---|---|
| 只有地址 + 业态 + 面积 | **商圈初选**：这片区域里哪些位置值得去现场看 | 零 Key、零接口消耗 |
| **加上月租金**（能换算成元/月、且 ≥ 1000） | **单点评估**：高德 + 腾讯双源交叉校验，动线阻断精算 | 约 3 次腾讯 POI + 5 对步行 |
| **再加上毛利率、初始投资**（有月人力、月其他固定更准） | **财务锁盘**：保本营业额、极限租金、回本周期、租期现金流、敏感度 | 无额外消耗，纯本地计算 |

> **为什么「租金」是分水岭**：租金是现场谈出来的。有租金说明这单在真推进，值得花配额做双源校验；
> 只写「租金面议」就只能停在初选。金额必须能换算成「元/月」，三位数会被当成面积不敢认。

### 营业额不用你估，报告自己算

**这是这套工具最容易被误解的地方**：选址阶段你手里本来就没有营业额——店还没开，哪来的日销。
拿一个拍出来的营业额去算回本，等于用假设验证假设。

所以报告是**反过来算**的，下面三个数都不需要你给营业额：

| 算出来的数 | 怎么来的 | 回答什么 |
|---|---|---|
| **每月 / 每日最低业绩**（保本线，估算） | （月租 + 月人力 + 月其他固定）÷（毛利率 − 税率），得月；再 ÷ 30 得日 | 卖不到这个数就是亏 —— 这是硬线，也是你能自己算出来的那根线 |
| **常规日营业额（产能上限）** | 座位数 × 该业态正常翻台 × 客单价；座位数 =（面积 − 厨房面积）÷ 每座面积 | 这个面积正常能做多少 —— 远超它是吹，远低于它是面积选大了 |
| **目标回本所需日营业额** | 初始投资 ÷ 目标回本月数 ÷（毛利率 − 税率）÷ 30 | 想 24 个月回本，每天得卖到多少 |
| **常规月营业额** | 常规日营业额 × 30，或 建筑面积 × 该业态每㎡月营收基准 | 月租占月营业额多少（租售比就是这么来的） |

这里只有**最低业绩**是硬门槛，另外两个是「正常能做多少」和「想多久回本得卖多少」——三个数一摆，
「这门生意能不能做」你自己就能判断，不需要谁来估一个营业额。

**为什么最低业绩不用你估**：它只跟支出和毛利率有关，跟你卖多少无关。月租 15 万、人力加其他 16.5 万、
毛利率 62%，一天就得卖到 1.8 万才不亏——这个数在你签合同之前就是确定的，跟你开不开张没关系。

**不给的时候，报告这样估**：建筑面积 × 该业态每㎡月营收基准 ÷ 30，得到日营业额；月营业额 = 日营业额 × 30。
基准取自行业平均数（`data/benchmarks.json`，19 城 × 48 业态），不是谁拍出来的。两个口径在报告里分工：
**租售比、坪效按月算**，**保本线与产能按日算**。

估算值不会冒充实测：报告的《待确认的假设》里会写「日营业额 · 按业态坪效基准估算（未提供）」。
你哪天拿到同城同品牌店的真实日销/月营业额，替换掉它，结论会跟着变。

**只有这种情况才填营业额**：你手里有**同城、同品牌、同面积**店的实际日销或月营业数据，能从收银系统拉出来的那种。
填进去，报告会拿它和产能上限比对——低于产能 40% 会直接提示「面积与营收不匹配」。
没有实测值就别填：填了会把假设当成事实，报告反而失真。

### 直接照着说就行

> 帮我看广州天河珠江新城华夏路 12 号这个铺，做大型粤菜，面积 600 ㎡，月租 15 万，
> 毛利率 62%，一次性投入 350 万，目标 24 个月回本。

这一句里已经把三档都占了，出来的是完整财务报告。少给其中几项也没关系，
报告会把缺的标成「待确认」，告诉你补哪个数最划算。

### 有时间就填调研表（比口述准）

口述适合先看个大概；真要签约前，把下面这些填进调研表更靠得住：

| 类别 | 填什么 | 要求 |
|---|---|---|
| 必填 3 项 | 月租金、毛利率、初始投资 | 不给这 3 项，财务整段不计算 |
| **有实测才填** | **日营业额**（同城、同品牌、同面积店的实际日销） | 没有就别填，报告按租金与产能自己算（见上） |
| 建议填 | 月人力、月其他固定（物业水电杂费）、租期、目标回本周期 | 给了才能算保本额与建议租金 |
| 现场 6 项 | 排烟、电量（kW）、层高、消防门宽、燃气（m³/h）、车位数 | 填了才会出现在「场地核查」段 |
| 每行都要 | **数据来源**（谁说的 / 哪张单据）+ **可信度** 0–1 | 报告据此标「实测」还是「估算」 |

Excel 填完必须另存为 **CSV UTF-8**，存成 GBK 会整表读空且不报错。

### 不用给的东西

- **日营业额**：店还没开，本来就没有。报告按租金反推保本线、按面积算产能上限（见上）
- **点评评分、门店月售**：这类数据能刷，拿可刷的数据验证模型比不验证更糟，系统一律不采
- **「这店能不能开」的结论**：不裁决，只给待核实清单
- **行业平均值**：不用你找，内置基准库有 19 城 × 48 业态，报告会自动对标并注明是估算值


## 三、哪些指标可以调整

分三类，改之前先确认你要动的是哪一类。

### A 类：你自己给的数（最该核实，直接决定结论）

| 指标 | 含义 | 改它影响什么 |
|---|---|---|
| 毛利率 | 扣掉食材成本后的毛利比例 | 保本线与极限租金 |
| 月租金 | 房租，不含物业费 | 租售比与全部回本结论 |
| 月人力 | 工资 + 社保合计 | 保本日营业额 |
| 月其他固定 | 物业费、水电、杂费 | 保本日营业额 |
| 初始投资 | 装修 + 设备 + 押金 + 转让费 | 回本周期与 ROI |
| 租期 | 合同签几年 | 租期现金流表的长度 |
| 年租金递增 | 每年房租涨多少 | 租期累计现金 |
| 目标回本周期 | 你希望几个月回本 | 「建议租金」的锚点 |

这 8 个里有 7 个是**你能拿单据核实的**（租赁合同、装修报价单、工资表、物业水电单）。
只有「目标回本周期」是你自己定的经营目标，没有单据可核。报告会把它们单独列出来，
告诉你「核实后结论会怎么变」。

### B 类：业态基准值（不是你给的，是行业水位；觉得不对就换）

**规矩：基准值一律取自行业平均数**——不是拍脑袋定的，也不是某一家店的最好成绩。
库在 `data/benchmarks.json`（912 行 / 19 城 / 48 业态 / 12 品类），做法是
「1 列行业基数 × 城市系数缩放」，所以它是**行业平均水平**，不是某个城市的实测水位：
拿来判断「你给的数离不离谱」可以，拿它当「本城就是这个数」不行。

改法：换业态档案，或改 `params/<业态>.json` 里一个键；改完必须在 `param_source` 写明依据
（老板口述 / 同行对标 / 哪个月实测），说不清来源的数不作数。

| 指标 | 基准值 | 什么时候该改 |
|---|---|---|
| 目标回本周期 | 24 个月 | 你的资金成本高/低，或行业惯例不同 |
| 租售比健康线 / 警戒线 | 12% / 18% | 一线核心商圈可上调，社区店应下调 |
| 厨房占比 | 30% | 重后厨业态（火锅、烤鱼）要更高 |
| 每座面积 | 2.4 ㎡ | 快餐更小、正餐更大 |
| 正常翻台 / 翻台上限 | 2.5 / 3.5 次 | 茶楼与快餐差别极大 |
| 每㎡年营收基准 | 900 元 | 有本品牌实测值就换成实测值 |
| 客单价区间 | 40–200 元 | 按你的实际菜单价改 |
| 毛利率区间 | 50%–70% | 用来做内部比值校验，越界会反推 |
| 人力占比区间 | 18%–28% | 同上，最常用来发现「人力估少了」 |
| 每㎡投资区间 | 3000–5000 元 | 同上，最常用来发现「投入漏项」 |
| 综合税率 | 4.5% | 有实际税负就填实际值 |
| 装修摊销月数 | 60 个月 | 按你的折旧年限改 |

### C 类：找点位的旋钮（只影响「筛哪些点」，不影响财务结论）

| 旋钮 | 默认 | 怎么调 |
|---|---|---|
| 统计半径 | 1000 米 | 大店 1500，小店 800 |
| 候选数量 | 30 个 | 20–30 合适，太多跑不完现场 |
| 竞争惩罚系数 | 大店 0.8 / 小店 0.4 | 越怕竞争，值越大 |
| 需求四项权重 | 住宅 0.3 / 办公 0.2 / 咖啡 0.25 / 配套 0.25 | 四项必须相加为 1，否则直接报错 |
| 竞品关键词 | 粤菜 / 茶楼 / 烧腊 | 按业态改，太宽会把小档口算成对手 |

### 调参的三条规矩

1. **参数是校准现实的，不是校准结论的**——算出来难看就原样呈现，不为了好看改参数
2. **改过的数必须在报告的「待确认假设」里看得到来源**——说不清谁给的数，结论不作数
3. **改完重量一遍敏感度**——原本「不会翻转」的参数，改完可能就变成「会翻转」

## 四、出问题时先看这三行

| 报告里出现 | 真实含义 | 你该做什么 |
|---|---|---|
| 本段未执行 | 缺数据或没跑，**不是没问题** | 按报告给的补齐方式补数据 |
| 待核实 N 项 | 这些必须现场看过 | 签约前逐条打勾，缺一项就是风险 |
| 【估算】 | 该环节降级了（如没接路网，用直线距离估） | 结论只能当方向，不能当承诺 |
