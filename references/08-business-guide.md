# 业务侧使用指南（不写代码，只讲怎么用）

> 这份给**提需求的人**和**看报告的人**：怎么开口、报告怎么读、哪些数字能改。
> 接口、坐标系、脚本参数这些技术细节在 `README.md` 和其余 `references/` 里，这份不重复。

## 一、它到底回答什么问题

给一个铺位，它回答三件事：

1. **这块地方值不值得去谈**——周边有多少人、有多少对手、人怎么走过来
2. **租金谈到多少才不亏**——保本租金是多少、按你的回本要求最高能出到多少
3. **最可能栽在哪**——排烟/电量/消防/层高这些现场条件缺什么，哪几个数字估错了结论会翻

它**不回答「这店能不能开」**。证照、环评、消防验收由承租方去办，系统只列「待核实 N 项」，
不做裁决——判错一次就会误导决策，所以这条是硬规矩。

## 二、怎么提需求（说三句话就够）

### 三句话分别是

| 第几句 | 说什么 | 说多细 |
|---|---|---|
| 1 | **在哪** | 城市 + 地址；商场店说清楼层和铺号，街铺说清路口或门牌 |
| 2 | **做什么** | 业态（粤菜 / 茶楼 / 咖啡 / 火锅…）+ 面积（㎡），有层高更好 |
| 3 | **钱怎么算** | 月租金；再往下是日营业额、毛利率、初始投资 |

### 说到哪一步，决定你能拿到什么

| 你给到的信息 | 能出的结果 | 多花的代价 |
|---|---|---|
| 只有地址 + 业态 + 面积 | **商圈初选**：这片区域里哪些位置值得去现场看 | 零 Key、零接口消耗 |
| **加上月租金**（能换算成元/月、且 ≥ 1000） | **单点评估**：高德 + 腾讯双源交叉校验，动线阻断精算 | 约 3 次腾讯 POI + 5 对步行 |
| **再加上日营业额、毛利率、初始投资** | **财务锁盘**：回本周期、极限租金、租期现金流、敏感度 | 无额外消耗，纯本地计算 |

> **为什么「租金」是分水岭**：租金是现场谈出来的。有租金说明这单在真推进，值得花配额做双源校验；
> 只写「租金面议」就只能停在初选。金额必须能换算成「元/月」，三位数会被当成面积不敢认。

### 直接照着说就行

> 帮我看广州天河珠江新城华夏路 12 号这个铺，做大型粤菜，面积 600 ㎡，月租 15 万，
> 日营业额按 1.8 万估，毛利率 62%，一次性投入 350 万。

这一句里已经把三档都占了，出来的是完整财务报告。少给其中几项也没关系，
报告会把缺的标成「待确认」，告诉你补哪个数最划算。

### 有时间就填调研表（比口述准）

口述适合先看个大概；真要签约前，把下面这些填进调研表更靠得住：

| 类别 | 填什么 | 要求 |
|---|---|---|
| 必填 4 项 | 日营业额、毛利率、月租金、初始投资 | 不给这 4 项，财务整段不计算 |
| 建议填 | 月人力、月其他固定（物业水电杂费）、租期、目标回本周期 | 给了才能算保本额与建议租金 |
| 现场 6 项 | 排烟、电量（kW）、层高、消防门宽、燃气（m³/h）、车位数 | 填了才会出现在「场地核查」段 |
| 每行都要 | **数据来源**（谁说的 / 哪张单据）+ **可信度** 0–1 | 报告据此标「实测」还是「估算」 |

Excel 填完必须另存为 **CSV UTF-8**，存成 GBK 会整表读空且不报错。

### 三样东西不用给

- **点评评分、门店月售**：这类数据能刷，拿可刷的数据验证模型比不验证更糟，系统一律不采
- **「这店能不能开」的结论**：不裁决，只给待核实清单
- **行业平均值**：不用你找，内置基准库有 19 城 × 48 业态，报告会自动对标并注明是估算值

## 三、报告怎么读（先看三处，其余备查）

### 第一处：开头的「结论」

一句话定性 + 三个支撑数字。**只信这句话里的数字，别信形容词**。
看不懂术语先看报告末尾的《附：看不懂的话先看这里（白话版）》，24 条常用词都有白话解释。

### 第二处：「数据质量」段——先确认是单源还是双源

| 报告写的 | 意思 | 你该怎么用 |
|---|---|---|
| **双源**（高德 + 腾讯交叉校验） | 竞品与动线经过两家数据核对 | 数字可直接用于谈判 |
| **单源**（只有高德） | 没给租金、没做交叉校验 | 只作初判参考，别拿去压价 |

单源时报告**不会**说「双源交叉验证」。看到这句话就说明确实是双源。

### 第三处：财务段的三个数

| 看哪个 | 一句话含义 | 怎么用 |
|---|---|---|
| **回本·现金口径** vs **回本·会计口径** | 前者是「多久把本钱挣回来」，后者把装修折旧摊进去、更保守 | 两个差很多，说明投入结构重，谈判时要压装修或延租期 |
| **极限租金·保本** | 租金涨到这个数就刚好不赚不亏 | 这是你的**绝对天花板**，超过它谈都不用谈 |
| **极限租金·目标回本** | 租金到多少仍能在你要求的月数内回本 | 这是你的**谈判锚点**，报价从这里往下压 |

再往下一格是**敏感度**：每个参数 ±20% 看结论会不会翻。被标成「**会翻转**」的那几个参数，
就是**必须去实测、不能拍脑袋**的——估错 20%，结论就从能做变不能做。

### 其余章节什么时候翻

| 章节 | 什么时候看 | 一句话怎么读 |
|---|---|---|
| 竞品分布 | 想知道对手多不多、强不强 | 「势力份额」是**谁离得近**，不是谁卖得多 |
| 截流判定 | 判断客人会不会被半路截走 | 两轴：点位截流力 L1–L5（位置好不好）+ 竞争截流（重度/轻度/无） |
| 竞品三级分层 | 判断谁才是真对手 | 只数「同品类 + 同价位段」的直接竞品，别被总数吓到 |
| 交通可达 | 判断人怎么来 | 最近地铁步行几分钟、有没有停车位 |
| 需求侧 | 判断客从哪来 | 全是**代理指标**（小区/写字楼/咖啡/配套密度），不是客流实测 |
| 场地核查 | 签约前逐条打勾 | 全 0 **不等于**核查通过，只等于规则没被触发 |
| 租期现金流 | 谈长约时 | 看第几年开始累计为正、中间要不要二次翻新投入 |
| 空间容量 | 面积和座位对不上时 | 座位数 × 翻台 = 日产能上限，产能不够就是面积买大了或买小了 |
| 行业基准对标 | 想验证数字离不离谱 | 偏离行业均值 3 倍以上，先怀疑自己给的那几个数 |
| 附录 | 想复核某个数 | 每个数字都有公式 + 本次代入值 + 结果 |

### 四个最常见的误读

1. **把「势力份额」当营业额份额**——它算的是「这块地盘谁离得最近」，占 60% 只说明它店多店近，不代表卖得多
2. **把人口当客流**——报告里的人口是**常住人口**（栅格估算），不是逛街的人；两者要分开看
3. **把「全 0 / 本段未执行」当成没问题**——未执行 = 还没查，不是查过了
4. **拿初选的分数跨批次比**——初选打分是**本批内的相对值**，换一批候选就不可比；跨城市比绝对密度

## 四、哪些指标可以调整

分三类，改之前先确认你要动的是哪一类。

### A 类：你自己给的数（最该核实，直接决定结论）

| 指标 | 含义 | 改它影响什么 |
|---|---|---|
| 日营业额 | 一天卖多少钱 | 整份测算的分母 |
| 毛利率 | 扣掉食材成本后的毛利比例 | 保本线与极限租金 |
| 月租金 | 房租，不含物业费 | 租售比与全部回本结论 |
| 月人力 | 工资 + 社保合计 | 保本日营业额 |
| 月其他固定 | 物业费、水电、杂费 | 保本日营业额 |
| 初始投资 | 装修 + 设备 + 押金 + 转让费 | 回本周期与 ROI |
| 租期 | 合同签几年 | 租期现金流表的长度 |
| 年租金递增 | 每年房租涨多少 | 租期累计现金 |
| 目标回本周期 | 你希望几个月回本 | 「建议租金」的锚点 |

这 9 个里有 6 个是**你能拿单据核实的**（合同、报价单、收款记录）。报告会把它们单独列出来，
告诉你「核实后结论会怎么变」。

### B 类：业态默认值（不是你给的，是内置的；觉得不对就换）

内置在 `params/` 里，换业态档案或改一个键就能覆盖：

| 指标 | 内置默认 | 什么时候该改 |
|---|---|---|
| 目标回本周期 | 24 个月 | 你的资金成本高/低，或行业惯例不同 |
| 租售比健康线 / 警戒线 | 12% / 18% | 一线核心商圈可上调，社区店应下调 |
| 厨房占比 | 30% | 重后厨业态（火锅、烤鱼）要更高 |
| 每座面积 | 2.4 ㎡ | 快餐更小、正餐更大 |
| 正常翻台 / 翻台上限 | 2.5 / 3.5 次 | 茶楼与快餐差别极大 |
| 每㎡年营收基准 | 900 元 | 有本品牌实测值就换成实测值 |
| 客单价区间 | 40–200 元 | 按你的实际菜单价改 |
| 毛利率区间 | 50%–70% | 用来做内部比值校验，越界会反推 |
| 人力占比区间 | 18%–28% | 同上，最常用来发现「人力估少了」 |
| 每㎡投资区间 | 3000–5000 元 | 同上，最常用来发现「投入漏项」 |
| 综合税率 | 4.5% | 有实际税负就填实际值 |
| 装修摊销月数 | 60 个月 | 按你的折旧年限改 |

### C 类：找点位的旋钮（只影响「筛哪些点」，不影响财务结论）

| 旋钮 | 默认 | 怎么调 |
|---|---|---|
| 统计半径 | 1000 米 | 大店 1500，小店 800 |
| 候选数量 | 30 个 | 20–30 合适，太多跑不完现场 |
| 竞争惩罚系数 | 大店 0.8 / 小店 0.4 | 越怕竞争，值越大 |
| 需求四项权重 | 住宅 0.3 / 办公 0.2 / 咖啡 0.25 / 配套 0.25 | 四项必须相加为 1，否则直接报错 |
| 竞品关键词 | 粤菜 / 茶楼 / 烧腊 | 按业态改，太宽会把小档口算成对手 |

### 调参的三条规矩

1. **参数是校准现实的，不是校准结论的**——算出来难看就原样呈现，不为了好看改参数
2. **改过的数必须在报告的「待确认假设」里看得到来源**——说不清谁给的数，结论不作数
3. **改完重量一遍敏感度**——原本「不会翻转」的参数，改完可能就变成「会翻转」

## 五、出问题时先看这三行

| 报告里出现 | 真实含义 | 你该做什么 |
|---|---|---|
| 本段未执行 | 缺数据或没跑，**不是没问题** | 按报告给的补齐方式补数据 |
| 待核实 N 项 | 这些必须现场看过 | 签约前逐条打勾，缺一项就是风险 |
| 【估算】 | 该环节降级了（如没接路网，用直线距离估） | 结论只能当方向，不能当承诺 |
