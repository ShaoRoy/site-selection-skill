# 偏好台账

> 这里记的是**用户反复纠正过、已经定型**的偏好与口径。
> 它优先于 `references/` 里的其他说明，也优先于模型自己的经验判断。
>
> **追加方式**：新偏好直接往对应小节加一行，写清「结论 + 为什么 + 怎么判」。
> 不需要改 SKILL.md，也不需要改人格提示词。

## 一、三条已定口径（不重开讨论）

| # | 结论 | 为什么 | 怎么判 |
|---|---|---|---|
| 1 | **人口数据用 POI 代理 + WorldPop 栅格，不再找第三方客流热力** | 公开渠道拿不到可信客流；商业人口库版权与口径都不透明 | 报告里人口只来自 WorldPop，且必须标「常住人口，非客流」 |
| 2 | **场地条件只提醒、不裁决；不输出「能否开业」式结论** | 证照与环评由承租方办理，业务链条自己会卡；系统判错一次就会误导决策 | 输出「待核实 N 项」而不是「硬伤否决」；不出现「这个铺不能开」 |
| 3 | **楼层维度去重只适用于大型商超** | 街铺跨层是不同铺位，商场内跨层常是同一门店的多楼层登记 | 非商超场景不做楼层合并 |

## 二、数据纪律

| 偏好 | 说明 |
|---|---|
| 不用可刷数据验证模型 | 点评评分、门店月售一律不采。用可刷数据验证不可刷模型，比不验证更糟 |
| 缺数据显式披露 | 写「本段未执行」+ 补齐命令；不塞空值、不用行业平均值兜底 |
| 每数可取 | 公式 + 本次代入值 + 结果，三件套齐全才叫给了数字 |
| 说人话 | 不用 Rev / GP / C_rent 这类符号，用「月营业额」「月固定成本」 |
| 不为凑结论反向调参 | 参数是校准现实的，不是校准结论的。难看就原样呈现 |

## 三、口径细节（容易搞错的）

| 项 | 正确 | 错误 |
|---|---|---|
| 竞品数 | 用去重后 `effective` | 用原始条数 |
| 座位翻台 | 客流 ÷ 座位数 | 与桌翻台混用 |
| 坪效 | 按**建筑面积** | 按营业面积（会虚高） |
| 保本日营业额 | 固定成本 × 成本乘数 ÷ (毛利率 − 税费率) ÷ 30 | 漏掉税费率 |
| 谈判锚点 | **基准档**极限租金 | 保守档（压力测试值不作出价依据） |
| 保本红线 | 基准档保本上限 | 保守档（那是压力红线，单独并列） |
| 最近竞品距离 | `dedupe.nearest`（去重后的唯一真相） | 圈层里另算一个（会出现 40m 与 41m 并存） |
| 图例家数 | 分开写「圈内 N 家」与「图中共 M 点」 | 只写一个数（会被读成矛盾） |
| 基准库结论 | 只看**偏离方向**（该库是 1 列基数 × 城市系数缩放） | 当作该城市实测水位 |

## 四、交付与表达

| 偏好 | 说明 |
|---|---|
| 先要齐数据再动手 | 财务参数一次问完 5 个，不要挤牙膏式追问 |
| 三类话不问 | 不问「你想要什么风格」、不问「要多长」、不问「要不要我继续」 |
| 缺参数就标待补 | 宁可输出残缺，不输出假完整 |
| 结论先行 | 一句话 + 三个支撑数字，再展开 |
| 每段可缺席 | 但缺席必须写明原因与补齐方式 |
| 不主动加免责声明 | 报告本身已含口径说明，不加「仅供参考」这类空话 |

## 五、工程约定

| 约定 | 说明 |
|---|---|
| 版本号每次 +0.0.1 | WorkBuddy 平台硬约束，不升版会判「未通过更新」 |
| 改代码只改 `scratch-plugin/` | 再同步到 `dist/site-selection-skill/`，由它派生另两包 |
| 改完必须跑基线 | 见 `06-regression-and-failure-modes.md` |
| 踩过的坑写进台账 | 不靠记忆；新坑补进 06 第二节 |
| 不硬编码参数 | 所有可调项走 `params/` 或 `--overrides` |

## 六、本台账的维护规则

1. **只记已经定型的**。还在讨论中的不进这里。
2. **每条写「结论 + 为什么 + 怎么判」**，缺一项就会在下次被重新翻案。
3. **与 SKILL.md 冲突时以本文件为准**，并回头修 SKILL.md——不能两边都留着。
4. **不删只归档**。过时的偏好移到文末「已废止」小节，写明废止原因与替代条目。
